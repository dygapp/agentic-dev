# 外部操作规范

Repository、Issue / PR、workflow、部署、远程服务和其他外部可变状态的写操作遵守以下边界。

## 先确认授权

工具可写、认证成功或 API 可用不等于已经获得操作授权。merge、release、deploy、生产变更、破坏性清理和共享历史改写必须服从当前 Repository / Human Authority。

## 最小必要变化

一次操作只完成当前目标需要的最小变化。存在等价方案时优先选择更可逆、影响面更小且更容易验证的路径。创建具有持续身份的远程对象前，先检查当前范围是否已有可继续使用的对象，避免因重试重复创建。

## 写后重新读取

写 API 返回成功只证明请求被接受或执行，不证明目标状态已经成立。写入后重新读取目标事实来源；结果不符合预期时重新分析，不基于假定状态继续。
