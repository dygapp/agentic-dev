# 中文交互与上下文清理 v1

## 1. 目标

本里程碑解决 `agentic-dev` 在项目开发、复核和状态汇报中长期存在的中英文混用问题，并降低历史会话、个人记忆和旧示范语料对后续 Agent 默认表达风格的干扰。

目标状态是：

> 面向人的内容默认使用自然、完整、易读的中文。只有为了保持机器可识别性、外部正式名称或精确引用而确有必要时，才保留原始英文。

这是一项仓库治理与行为可靠性工作，不改变核心开发方法生命周期，也不新增工程能力层。

## 2. 启动决定

人工权威已明确选择该问题作为上一轮里程碑完成后的下一有限里程碑。

跟踪入口：Issue #62。

`master@9818b3209a80bba22c6fbec2af740f49a17fa2d4`

## 3. 问题定义

当前问题不只是个别文档写法不统一，而是三个来源相互强化：

1. 仓库现有术语规范把“中文主述、英文锚定”作为推荐模式，使大量可直接用中文表达的概念仍反复出现英文；
2. `AGENTS.md`、`README.md`、使用指南、复核规则及历史示例持续向新上下文展示中英文混排，容易被 Agent 学习成默认项目语风；
3. 历史会话和账户级个人记忆可能继续保存旧项目表达习惯。它们不属于仓库权威，但如果运行环境主动提供，仍可能影响生成风格。

因此，本里程碑必须同时处理仓库规则、示范语料、行为验证和账户级记忆边界。

## 4. 范围

### 4.1 语言治理

- 将当前语言规则收紧为“自然中文默认、必要原始标识例外”；
- 稳定中文概念不再机械附带英文解释；
- 状态汇报、计划、Issue / PR、复核意见、人工验收说明和其他面向人的交互全部纳入规则；
- 明确历史会话、其他会话和个人记忆不能决定项目事实，也不能替代当前仓库的语言规则。

### 4.2 高影响入口收敛

优先清理会被新上下文直接读取、并会塑造 Agent 默认输出方式的现行入口：

- `AGENTS.md`；
- `README.md`；
- `docs/guides/terminology-guidelines.md`；
- `docs/guides/using-agentic-dev.md` 中直接影响语言选择的规则与示例；
- `docs/guides/external-operation-guidelines.md` 中外部协作语言规则；
- `docs/project/ai-review-guidelines.md` 中语言复核标准；
- 本里程碑新增的项目与评估材料。

其他历史研究、已关闭计划、旧证据和 Git 历史不为了表面一致性整体重写。它们不再作为当前语言示范；实际被重新启用或实质修改时，再按现行规则收敛。

### 4.3 行为验证

增加针对中文输出稳定性的行为评估，至少覆盖：

- 新上下文恢复项目状态并向人工汇报；
- 规划或验证结果汇报；
- PR / Issue 复核结论；
- 输入中夹杂大量英文术语时仍按仓库规则输出自然中文。

评估必须检查语义正确性与语言可读性，不能只检查是否出现中文字符。

## 5. 允许保留英文的边界

以下内容默认保持原样：

- 代码标识符、配置键、枚举值和必须精确匹配的状态值；
- 文件名、路径、命令、命令参数；
- API / CLI 名称和参数；
- Git 分支、提交哈希、Issue / PR 编号；
- 技能的正式目录名或调用名；
- 外部产品、框架、协议和规范的正式名称；
- 错误信息、日志和需要原样引用的外部文本。

即使允许保留英文，也应让句子主体保持自然中文；不得把英文对象进一步扩散成整段英文叙述。

## 6. 非目标

- 不修改核心方法阶段或技能契约；
- 不新增工程纪律、技术画像、任务型技能或运行时适配器；
- 不强制翻译会破坏机器匹配或外部引用精度的固定标识；
- 不通过批量替换制造大规模无语义价值的历史差异；
- 不声称仓库工具能够删除 ChatGPT 账户级记忆。

## 7. 账户级记忆与最终验收边界

仓库权威只能约束项目持久规则，不能直接删除 ChatGPT 账户级记忆。

本里程碑要求最终交付时明确提示人工：

1. 在 ChatGPT 的个性化设置中检查并修改 `Memory summary`；
2. 删除仍保存旧 `agentic-dev` 项目规则、语言习惯或旧提示词模式的原始聊天及其他来源；
3. 仅归档聊天不能作为彻底移除依据；
4. 清理后重新建立一个真正的新上下文，并在不添加“请使用中文”等语言纠正提示的情况下执行最终语言验收。

PR 合并前的最终验收是对**拟集成候选状态**的行为验证，不把未合并 PR 提升为当前 `master` 权威。验收上下文应：

- 读取当前 `master` 仅用于确认集成基线和 GitHub 当前事实；
- 明确读取 PR #63 当前提交及其 `AGENTS.md`、`README.md`、项目路线图和本里程碑文档，作为本次拟集成候选状态；
- 以 PR #63 当前提交中的候选语言规则判断拟集成后行为是否成立；
- 不从 `master` 的旧语言示例继承候选状态已经明确取代的表达习惯；
- 不通过额外语言纠正提示帮助模型通过验收。

如果验收只先读取尚未集成新规则的 `master`，再把默认分支旧语风带入回答，该结果不能证明 PR #63 的拟集成状态通过或失败，应视为验收目标引用错误并重新执行。

Agent 不得声称账户级内容已经由仓库修改自动删除。
