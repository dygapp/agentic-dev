# 仓库基线

## 仓库

```yaml
name: agentic-dev
platform: github
repository: https://github.com/dygapp/agentic-dev
source_of_truth: true
```

上述 YAML 字段属于机器可读配置示例，保持原样。

## 唯一事实来源规则

`agentic-dev` 的 GitHub 仓库是项目长期演进的唯一基线来源。

- Git 提交记录可追溯的项目演进历史；
- 分支隔离尚未进入共享基线的设计、实验和实现工作；
- Pull Request 是可选的人工复核机制，是否使用以及如何合并由仓库策略或人工权威决定；
- 当工作基于非默认分支或特定提交时，应显式说明对应 Git 引用，避免不同 Agent 基于不同仓库状态作出判断。

ZIP 快照仅用于：

- 初始项目导入；
- 离线交换；
- 临时备份。

ZIP 不作为持续开发过程中的权威上下文来源；如果 ZIP 与 Git 仓库状态不一致，以当前明确指定的 Git 引用为准。

## 协作模型

仓库是人工与 Agent 之间共享的长期上下文载体。会话历史、临时输出和本地 ZIP 都不能替代已经进入仓库的权威产物。

典型协作过程可以是：

```text
人工 / Agent 决策
      ↓
权威产物 / 任务
      ↓
已授权 Agent 工作
      ↓
验证 / 复核
      ↓
工作分支 Git 提交
      ↓
人工 / 仓库策略
      ↓
共享仓库基线
```

这里不把 ChatGPT、Codex 或其他 Agent 固定为只读或只写角色。具体 Agent 能否读取、修改、提交或评审仓库，由当前任务授权、仓库策略、工具能力和变更风险共同决定。

## 权威边界

- Agent 可以在已授权范围内分析、设计、修改、验证和复核仓库内容；
- 普通、低影响、可逆的仓库内变更可以由 Agent 按当前授权继续执行；
- 会改变方法意图、重大架构方向、具有破坏性或不可逆影响、安全 / 隐私敏感，或超出当前授权的事项必须升级给人工；
- 合并、发布、部署和其他共享状态变更继续受 `AGENTS.md` 与仓库策略 / 人工权威约束。

## 工作基线规则

开始一项工作时，优先从 Git 仓库获取当前状态。

- 未指定 Git 引用时，使用仓库当前默认基线；
- 已指定分支 / 提交时，以该 Git 引用作为本轮工作的明确上下文；
- 工作过程中如果仓库状态已经发生变化，应重新确认当前 Git 引用，而不是依赖先前会话中缓存的文件内容；
- 任何需要长期保留的方法、契约、架构或实现结论，都必须最终进入仓库中对应的权威产物，而不能只停留在聊天或任务记录中。
