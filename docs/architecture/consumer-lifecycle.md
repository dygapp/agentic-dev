# 使用方初始化、采用、升级与普通运行生命周期

**状态：** 候选 v0.1（V3-03）  
**性质：** 规范性可复用工程能力架构  
**跟踪：** Issue #104

## 1. 目的

本文单点定义使用方使用 `agentic-dev` 时的长期生命周期语义：

- 新使用方如何建立最小本地权威并完成首次采用；
- 已有使用方如何显式评估新的上游基线；
- 可复用变化如何逐项形成采用决定；
- 已采用变化如何形成使用方本地当前能力；
- 首次采用或基线升级何时可以声明完成并推进上游评估基线；
- 完成后为什么普通运行必须回到使用方本地；
- 哪些条件允许显式重新进入上游。

“使用方生命周期”的正式英文身份为 `Consumer Lifecycle`。本文定义的是可复用工程能力，不是软件产品开发阶段；它不新增 `docs/method/ai-development-method.md` 中的方法阶段，也不替代使用方仓库权威、技能契约、资源发现架构或具体平台过程。

## 2. 权威与边界

本文属于跨仓库可复用工程能力。发生冲突时：

1. 使用方自己的仓库权威决定项目事实、授权、集成策略与本地当前有效状态；
2. `agentic-dev` 核心方法与原则决定通用开发阶段、职责和完成语义；
3. 本文只拥有上游采用、升级、普通运行与重新进入上游的生命周期语义；
4. 技能职责、输入、过程、退出和阶段返回由技能架构、技能契约与 `SKILL.md` 拥有；
5. metadata、Manifest、Catalog、source identity 与资源发现 / 路由的具体结构和算法由后续资源模型与发现架构拥有；
6. 使用方验证阶段只验证本文及其他所有者定义的行为，不取得这些规则的语义所有权。

因此必须保持：

```text
使用方生命周期
≠ 产品开发方法阶段
≠ 技能执行过程
≠ 资源发现实现
≠ 使用方项目事实
```

## 3. 核心不变量

### 3.1 必须显式采用

上游可复用能力不会因为存在、被读取、被复制或版本更高就自动进入使用方当前状态。

必须经过：

```text
固定上游候选
→ 与使用方当前权威比较
→ 逐项决定
→ 形成使用方本地持久结果
```

### 3.2 来源不等于当前权威

采用完成后：

```text
上游来源
≠ 使用方当前权威
```

`adopted_from` 等来源记录只说明来源，不把未来的上游提交变成使用方的自动更新通道。

### 3.3 上游评估基线不等于当前资产来源

必须分离三类状态：

- **上游评估基线**：使用方最近完整比较并完成采用判断的精确上游基线；
- **当前本地资产来源**：每个当前本地能力实际采用或演进自哪个来源；
- **仅升级使用的决策历史**：此前 `retain / override / reject / supersede` 等升级判断记录。

三者不能由一个“当前基线”字符串代替。

### 3.4 逐项采用，不做整库继承

基线升级的判断单位是对使用方具有持续意义的可复用变化，而不是整个上游仓库。

至少逐项区分：

- `adopt`：采用；
- `retain / override`：保留或本地覆盖；
- `reject / not applicable`：拒绝或不适用；
- `supersede / remove`：取代或移除。

上游项目专属状态、Research / Eval 与历史证据默认不投射为使用方普通运行权威。

### 3.5 现有本地语义所有者优先

如果使用方已有正确的语义所有者承载待采用变化，应更新现有所有者，而不是机械增加一份上游副本。

目标是：

```text
一个当前语义所有者
+ 可选的来源 / 决策证据
```

而不是：

```text
本地规则正文
+ 上游复制正文
+ 发现摘要正文
```

### 3.6 采用完成前必须验证

首次采用或基线升级只有在必要验证完成后才能声明完成，并推进上游评估基线。

本文拥有“必须验证后才能完成采用 / 升级”这一生命周期责任；具体被验证规则、测试方式、平台步骤和证据声明仍由各自语义所有者、使用方仓库权威与验证能力决定。

### 3.7 普通运行仅依赖本地当前状态

采用完成后，使用方普通运行必须只依赖使用方本地当前状态，不把上游仓库作为持续运行依赖。

### 3.8 重新进入上游必须显式

上游新提交、模型好奇、本地发现信息陈旧或路由歧义，都不能自行触发“读取最新上游并改变当前行为”。重新进入上游必须满足本文定义的显式条件。

### 3.9 同时控制上游和使用方两侧当前有效性

一次采用 / 升级同时依赖两个不同边界：

- 上游候选必须固定为精确标识；评估期间出现的新上游提交不自动进入本次范围；
- 使用方仓库权威与本地所有者必须在完成前重新确认仍与采用决定的比较前提一致。

如果使用方在评估期间发生与本次可复用变化相关的实质变化，只重算受影响的分类、决定与验证，不机械重启全部升级，也不能继续使用已失效的旧决定直接推进基线。

## 4. 生命周期状态模型

本文定义五个语义状态。实现不要求使用这些名称作为字段、枚举或目录。

### 4.1 初始化中

适用于尚未完成首次采用的新使用方。

目标是建立足以继续工作的最小使用方本地权威，而不是复制完整 `agentic-dev` 结构。

允许形成：

- 稳定的仓库启动入口与权威边界；
- README 或等价人类入口；
- 当前真实需要的需求、规格说明、架构、验证与集成权威；
- 当前需要采用的可复用能力；
- 必要的 Roadmap / Task / Plan，但只在真实协调需求存在时建立。

不允许为了模板完整预建空 Requirement、Architecture、ADR、Skill、Catalog 或历史目录。

### 4.2 采用评估中

适用于首次采用，也适用于已有使用方的显式基线升级。

此状态允许读取上游，但必须固定候选来源与比较边界，并针对可复用变化做逐项决定。

### 4.3 本地投影待验证

逐项决定已经形成，使用方本地候选语义所有者 / 能力已按需要更新，但采用 / 升级尚未完成。

此时：

- 候选上游基线不能被声明为新的上游评估基线；
- 未验证的候选资产不得仅因被写入工作分支或临时目录就自动成为普通运行的当前所有者；
- 当前有效性仍由使用方自己的仓库权威与集成策略决定；
- 已有使用方不得因为升级未完成就丢失原有可用当前所有者。

### 4.4 普通运行

首次采用或升级验证完成后的稳定状态。

普通新上下文只消费使用方本地当前状态；上游只保留来源追溯与未来显式升级意义。

### 4.5 请求重新进入上游

使用方在普通运行中命中显式重新进入条件时进入的过渡判断状态。

它只决定是否允许访问上游，以及获准后进入采用 / 升级路径，还是进入受限的只读比较、研究、实验或验证路径；不授权直接用上游内容覆盖本地当前所有者。

### 4.6 合法状态转换

状态名称只是语义模型，但转换边界必须一致。合法采用主路径为：

```text
新使用方
初始化中
→ 采用评估中
→ 本地投影待验证
→ 普通运行

已有使用方
普通运行
→ 请求重新进入上游
→ 采用评估中
→ 本地投影待验证
→ 普通运行
```

不产生采用的重新进入路径为：

```text
普通运行
→ 请求重新进入上游
→ 经授权的读取 / 比较 / 研究 / 实验 / 验证
→ 只形成分析或证据
→ 普通运行
```

其中：

- 新使用方只有在需要采用上游可复用能力时进入“采用评估中”；如果当前没有需要采用的可复用能力，仍必须满足最小使用方仓库权威与可恢复普通工作的要求后才能进入“普通运行”，不得为了形式完整制造一次空采用；
- 已有使用方的任何上游重新进入都先经过“请求重新进入上游”的条件判断；显式基线升级是使该判断成立的条件之一，而不是绕过重新进入边界的另一条隐式路径；
- 获准访问上游后必须根据明确任务意图区分采用路径和非采用路径；仅阅读、比较、研究、实验或验证不自动转化为采用；
- 非采用路径只能形成分析、证据或反馈，不更新使用方本地当前所有者，不推进上游评估基线；若随后决定采用，必须显式进入“采用评估中”；
- “采用评估中”只有在当前相关可复用变化已完成逐项决定后才能进入“本地投影待验证”；
- “本地投影待验证”只有在采用验证、使用方侧当前有效性复核和基线推进门禁都满足后才能进入“普通运行”；
- 任一采用 / 升级流程失败或中断，都不得用状态跳转绕过第 9.3 节的部分完成规则；已有使用方的旧当前状态继续按使用方仓库权威保持有效，新使用方则保持未完成初始化 / 采用状态，不伪装成已完成普通运行。

V3-05 / V3-06 可以为这些语义状态设计表示形式或发现行为，但不得新增另一套冲突的生命周期转换。

## 5. 新使用方初始化与首次采用

### 5.1 先建立使用方身份，再采用可复用能力

新项目启动不是“安装 `agentic-dev` 模板”。应先确定：

- 使用方仓库身份；
- 使用方仓库权威与知识边界；
- 当前目标与人工授权边界；
- 当前明确输入；
- 最小验证 / 集成策略；
- 当前真正需要的可复用能力。

`agentic-dev` 自身 Roadmap、Issue / PR、当前里程碑、仓库提交习惯和项目专属政策不自动继承。

### 5.2 原始需求输入与使用方权威

原始需求、外部文档和研究资料默认是输入，不因为存在于仓库或自身带有 `approved` / `confirmed` 等标签就自动成为使用方权威。

如果人工已明确指定某份资料为当前权威需求，可以直接按该授权建立其使用方权威身份，不要求重复形式审批；仍需明确当前范围、优先级和无法解析的外部引用。

如果没有原始需求，不制造空 Requirement。后续在真实产品意图出现时由相应方法 / 技能职责形成。

### 5.3 首次采用与普通项目初始化分离

使用方原生项目权威与可复用能力采用可以在同一初始化工作中完成，但语义必须分离：

```text
使用方原生项目事实
≠ 采用得到的可复用能力
```

首次采用只选择当前使用方真实需要、具有持续约束或能力价值的可复用内容。

### 5.4 首次采用完成门禁

首次采用只有在以下条件满足后才能离开初始化 / 采用流程：

1. 使用方有可恢复的最小仓库权威；
2. 上游候选精确标识已固定；
3. 当前相关可复用项已逐项判断；
4. 已采用项已形成使用方本地持久语义所有者 / 能力；
5. 拒绝 / 不适用项不进入普通运行当前集合；
6. 使用方特定覆盖与优先级保持明确；
7. 必要采用验证已完成；
8. 使用方侧当前有效性在完成前已重新确认；
9. 首个上游评估基线可以被真实记录；
10. 新上下文不依赖上游即可继续普通工作。

如果新使用方当前没有采用任何上游可复用能力，则不要求制造虚假的上游评估基线；此时只需完成最小使用方仓库权威 / 恢复门禁，即可进入普通工作，未来首次真实采用时再建立上游评估基线。

## 6. 已有使用方基线升级

### 6.1 基线升级是显式低频操作

已有使用方不在普通任务中持续跟随上游最新状态。一次基线升级必须由使用方仓库权威、维护者或明确任务显式启动，并先满足“请求重新进入上游”的条件判断。

### 6.2 升级最小输入

通常至少需要：

- 使用方当前仓库权威；
- 当前使用方本地能力 / 发现状态；
- 上一次上游评估基线；
- 候选上游精确基线；
- 两个基线之间实际的可复用变化；
- 与当前变化相关的保留、覆盖、拒绝历史；
- 当前使用方技术栈、平台、验证与项目约束中的最小必要事实。

如果上一次上游评估基线缺失、无法验证，或使用方属于迁入本模型前的旧状态，不得根据本地文件时间、旧聊天或猜测伪造基线。此时应把候选基线视为一次显式的**基线恢复 / 首次完整评估**：以使用方当前仓库权威和可验证的当前资产来源为事实边界，对当前真正相关的可复用范围做足够覆盖的首次比较，并记录历史不确定性；只有完成逐项决定与验证后才建立新的上游评估基线。

不为了升级读取完整历史聊天或无关的上游项目历史。

### 6.3 上游变化先分类，再决定

至少区分：

- 核心方法 / 原则；
- 技能 / 技能契约；
- 工程纪律；
- 技术画像 / 验证画像；
- 可复用 Guide / 生命周期 / 运行能力；
- 运行时适配 / 平台能力；
- `agentic-dev` 项目专属内容；
- Research / Eval / 历史证据。

只有使用方可能持续消费的可复用变化进入采用决定。

### 6.4 使用方侧漂移

在进入基线推进前，必须确认与本次决定相关的使用方当前仓库权威 / 本地所有者是否仍与比较时一致。

如果出现实质漂移：

- 识别受影响的可复用项 / 本地所有者；
- 只对这些项重新执行必要分类、采用 / 保留 / 拒绝 / 取代决定与验证；
- 无关项可以保留已经验证的结论；
- 不把整个升级机械作废，也不得无视漂移使用陈旧决定；
- 如果无法安全判断漂移影响范围，则失败关闭，扩大使用方本地权威读取或升级给人工，而不是用上游候选覆盖本地变化。

## 7. 单项采用决定

### 7.1 `adopt` — 采用

适用于使用方需要该可复用变化，且与使用方当前仓库权威不冲突。

结果：

- 创建或更新正确的使用方本地语义所有者 / 能力候选；
- 保留真实 `adopted_from` 来源；
- 必要时更新本地发现表示候选；
- 进入采用验证；
- 在验证 / 集成门禁满足前，不因候选已写入而自动宣称它是普通运行当前所有者。

### 7.2 `retain / override` — 保留或覆盖

适用于使用方已有更具体的合法本地规则，或明确继续保留旧本地行为。

结果：

- 当前本地所有者保持；
- 记录候选上游基线已经被评估；
- 必要时记录覆盖 / 保留关系；
- 不伪造当前资产已采用自候选基线。

### 7.3 `reject / not applicable` — 拒绝或不适用

适用于当前使用方不使用对应平台 / 能力、变化只属于上游自身，或使用方明确不采用。

结果：

- 只在升级历史中保留必要判断；
- 不创建普通运行当前记录；
- 不复制规范正文；
- 不制造禁用占位记录只为“目录完整”。

### 7.4 `supersede / remove` — 取代或移除

适用于现有本地已采用能力经新的显式决定不再当前有效。

结果必须保证：

- 新的当前所有者已经可用并通过相应验证，或使用方明确决定该能力不再需要；
- 旧资产从当前路由 / 活动集合退出；
- 历史来源可以保留；
- 新旧两份正文不能同时被解释为当前所有者。

在替代项尚未完成验证 / 集成时，“取代或移除”只是待完成决定；不得提前移除已有使用方当前仍需要的旧所有者。

## 8. 三类基线与来源状态

### 8.1 上游评估基线

只回答：

> 使用方最近完整评估到哪个精确上游基线？

它是比较边界，不是本地所有资产的版本声明。

### 8.2 当前本地资产来源

每个当前本地已采用资产保留自己的真实来源。它可以早于当前上游评估基线，也可以经过使用方本地演进后不再与某个上游文件一一对应。

### 8.3 仅升级使用的决策历史

用于下一次升级理解此前的保留、覆盖、拒绝、取代决定。

它默认不进入普通新上下文，也不是普通运行当前权威。

### 8.4 重新评估旧决定

旧决定至少在以下情况下重新进入升级判断：

- 使用方技术栈或平台改变；
- 原先“不适用”的能力变为适用；
- 使用方本地覆盖被删除或实质变化；
- 上游后续变化再次修改同一语义所有者；
- 使用方实际使用证据表明旧判断不再成立。

## 9. 采用验证与基线推进

### 9.1 生命周期责任

所有首次采用和基线升级都必须在完成声明前验证使用方本地结果。

验证目标不是证明“上游是正确的”，而是证明：

- 当前采用 / 保留结果与使用方仓库权威一致；
- 当前所有者 / 取代关系没有产生双重所有者；
- 使用方本地普通运行路径仍能恢复；
- 被采用能力所要求的具体行为和证据满足其真实语义所有者的验收义务。

### 9.2 基线推进门禁

只有以下条件满足后，候选上游基线才能成为新的上游评估基线：

1. 候选上游精确标识已确认；
2. 上一次上游评估基线已确认，或已经按第 6.2 节完成显式基线恢复；
3. 可复用、项目专属、Research / Eval 与历史证据变化已经分类；
4. 使用方相关可复用变化均已逐项决定；
5. 采用 / 保留的本地所有者已按需要更新；
6. 拒绝 / 不适用项不进入普通运行当前集合；
7. 被取代旧资产不再作为当前所有者；
8. 使用方仓库权威优先级没有被上游覆盖；
9. 使用方侧相关当前有效性已在完成前重新确认，任何实质漂移已按第 6.4 节处理；
10. 生命周期层面的采用验证已完成；
11. 各具体语义所有者要求的必要验证已经满足；
12. 仅依赖本地当前状态的普通运行路径仍成立；
13. 基线推进没有被描述为“全部上游内容均已采用”。

如果使用方集成策略要求 PR、人工复核、合并或其他动作完成后，候选本地资产才能成为当前状态，那么相应集成门禁也是本次采用 / 升级完成的前置条件；本文不绕过使用方自己的集成策略。

### 9.3 失败或中断

任一关键门禁未完成时：

- 不推进上游评估基线；
- 不声明采用 / 升级完成；
- 不通过修改一个基线指针掩盖部分完成状态；
- 已有使用方原有当前所有者不因一次升级尝试自动失效；
- 候选本地变化的当前有效性继续由使用方自己的仓库权威与集成策略决定。

本文不强制使用方采用 PR、事务提交或某种回滚机制，但要求完成声明与真实当前状态一致。

## 10. 普通运行

### 10.1 默认只依赖本地

进入普通运行后，普通新上下文默认只读取：

- 使用方稳定启动入口 / 当前权威；
- 使用方本地当前发现入口；
- 当前任务命中的本地语义所有者；
- 当前真正需要的本地技能 / 能力；
- 当前工作与当前证据。

默认不读取：

- 上游仓库；
- 上游最新状态；
- 采用 / 升级决策历史；
- 上一次基线差异；
- 已拒绝候选；
- 上游 Roadmap / Issue / PR / 项目状态；
- 升级推理记录。

### 10.2 上游新提交不改变普通运行

上游从基线 B1 变化到 B2，只表示未来存在新的升级候选。

在使用方没有显式进入新的采用 / 升级流程前：

```text
使用方普通运行 @ 本地状态 L1
+ 上游 B1 → B2
=
使用方普通运行仍为 L1
```

### 10.3 本地发现问题不自动升级为上游依赖

如果本地发现信息陈旧、缺失或歧义，运行时应先按使用方本地发现 / 失败关闭规则回到使用方当前仓库权威。

这本身不是重新进入上游的条件。只有确认使用方本地必要可复用能力确实缺失，并且使用方仓库权威允许从上游重新解析时，才进入显式重新进入判断。

## 11. 重新进入上游

### 11.1 允许的显式条件

普通运行只有在以下至少一个条件成立时才重新进入上游：

1. 明确启动新的基线采用 / 升级；
2. 使用方本地必要可复用能力经确认缺失，且使用方仓库权威允许从上游解析 / 采用；
3. 当前任务被明确声明为 `agentic-dev` 实验 / 验证；
4. 使用方仓库权威明确要求读取或比较上游；
5. 新使用方正处于首次采用流程。

### 11.2 不构成重新进入条件的信号

以下情况单独存在时不允许自动读取上游并改变当前行为：

- 上游有新提交、tag 或 release；
- 本地 metadata / Catalog 陈旧；
- 路由出现歧义；
- Agent 尚不确定，但使用方当前仓库权威还没有读完；
- 某条上游规则看起来“更新”或“最佳实践更强”；
- 为了完整性想同步全部上游文档。

### 11.3 重新进入后先区分任务性质

允许访问上游不等于必须采用。获准后先区分两类路径。

**采用 / 升级路径**：任务明确要求首次采用、基线升级、补齐并采用缺失可复用能力，或在只读比较后又显式决定采用。此时必须经过：

```text
读取 / 比较上游
→ 分类
→ 逐项决定
→ 本地投影
→ 验证
→ 基线推进
```

**非采用路径**：任务只要求读取 / 比较、研究、实验 / 验证，或形成是否值得升级的证据。此时：

- 可以按授权读取所需上游；
- 输出只属于分析、研究、证据或反馈；
- 不修改使用方本地当前所有者；
- 不改变当前本地资产来源；
- 不推进上游评估基线；
- 完成后返回使用方本地普通状态；
- 后续若决定采用，必须重新显式进入“采用评估中”。

不能把“允许查看上游”解释成“允许覆盖使用方当前状态”，也不能把非采用比较伪装成已经完成的基线评估 / 推进。

## 14. 代表性场景

V3-03 的语义至少必须能一致解释以下场景：

| 场景 | 正确生命周期结果 |
|---|---|
| 新使用方有明确原始需求 | 建立最小使用方权威，按明确授权形成需求身份，再选择性首次采用可复用能力 |
| 新使用方没有原始需求 | 不制造空 Requirement；先建立最小治理骨架，后续按真实工作形成项目权威 |
| 新使用方当前无需任何上游可复用能力 | 不制造空采用或虚假基线；完成最小使用方权威后进入普通工作 |
| 已有使用方发现上游新基线 | 普通运行不变；只有显式升级经重新进入判断后才开始比较 |
| 已有使用方没有可验证的上一次基线 | 不猜测旧基线；以当前权威 / 来源做基线恢复，再建立首个上游评估基线 |
| 上游新规则与本地覆盖冲突 | 可 `retain / override`；推进评估基线时不伪造该资产来源 |
| 上游新 Skill 当前使用方不使用 | `reject / not applicable`，不进入普通运行当前集合 |
| 替代项尚未验证完成 | 旧当前所有者不提前退出；新候选不因写入分支自动成为当前 |
| 升级期间使用方本地所有者发生相关漂移 | 只重算受影响决定 / 验证；未处理前不推进基线 |
| 升级中途失败 | 不推进评估基线；不得声明升级完成；旧当前所有者不自动失效 |
| 本地发现信息陈旧 | 先失败关闭到使用方当前仓库权威，不自动在线读取上游 |
| 使用方明确缺少必要可复用能力 | 经使用方仓库权威允许后显式重新进入，再走采用流程 |
| 使用方仓库权威只要求比较上游 | 走非采用路径，只形成分析 / 证据，不修改本地当前状态或基线 |
| 明确 `agentic-dev` 实验 / 验证 | 可受限读取上游形成证据；实验本身不自动触发采用 / 基线推进 |
| 上游在普通运行期间继续提交 | 不改变使用方本地当前行为 |

## 15. V3-03 门禁

V3-03 只有在以下条件满足后才可以声明完成：

- 初始化、首次采用、基线升级、本地投影、采用验证、基线推进、普通运行和重新进入上游构成单一一致生命周期；
- 五个语义状态及其合法转换边界明确，不允许后续资源表示 / 发现实现重新定义第二套生命周期；
- 采用型重新进入与非采用的读取 / 比较 / 实验路径明确分离；
- 上游精确候选与使用方侧当前有效性两侧边界均受控制；
- 上一次上游评估基线缺失时失败关闭到显式恢复，不伪造历史；
- 上游评估基线、当前本地资产来源与仅升级使用的决策历史职责分离；
- `adopt / retain-or-override / reject-not-applicable / supersede-remove` 的决定语义稳定；
- 部分完成 / 失败升级不会制造假的完成状态或隐式覆盖；
- 仅依赖本地当前状态的普通运行不变量与显式重新进入条件清晰；
- 与核心方法、Guide、技能、V3-05、V3-06、V3-08 的语义所有权边界明确；
- v1 / v2 已验证的使用方本地优先、逐项采用、本地覆盖、来源分离、渐进式披露与失败关闭成果未被破坏；
- 高影响生命周期歧义经过与风险相称的 AI 复核后不存在未解决的阻塞或中等级问题。

达到门禁后，只进入“是否启动 V3-04”的规划判断；本文不授权物理 Guide 迁移、技能重构、metadata / discovery 实现或使用方仓库修改。
