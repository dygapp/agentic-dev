# Codex 多模型协同实验

## 状态与范围

本配置只用于 `experiment/codex-multi-model-collaboration` 分支中的 Codex 平台实验。它不修改通用方法、原则、工程纪律、技术画像或通用 Skill 契约，也不代表 WI-09 已经启动或多模型方案已经通过评估。

配置依据是 2026-09-08 获取的 [OpenAI Docs：Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[OpenAI Docs：Config basics](https://learn.chatgpt.com/docs/config-file/config-basic)、本地 `codex-cli 0.153.4` 及当时可见的模型目录。官方文档明确说明子代理通常比可比的单代理运行消耗更多令牌，因此本实验把工程质量作为前置门槛，再观察返工、时间和可观测用量。

## 角色映射

| 角色 | 自定义代理 | 当前模型 | 主要用途 | 权限 |
|---|---|---|---|---|
| 快速探索 | `fast_explorer` | `gpt-5.6-luna` / `medium` | 并行搜索、依赖定位、资料整理 | 只读 |
| 常规实施 | `implementation_worker` | `gpt-5.6-terra` / `high` | 单一有界工程修改与定向验证 | 工作区写入 |
| 工程复核 | `quality_reviewer` | `gpt-5.6-sol` / `high` | 正确性、回归和验证证据复核 | 只读 |
| 关键复核 | `critical_reviewer` | `gpt-6-astra` / `xhigh` | 高影响技术、方法、架构、安全或关键评估补充复核 | 只读 |

主代理由实验命令显式选择 `gpt-5.6-sol`，负责保存目标、权威、决策与最终输出。Astra 只在高影响触发条件成立时运行，不参加普通探索、常规实现或日常复核。

## 协同边界

- 只把相互独立的只读探索、分类、测试观察或复核任务并行化；
- 同一时间只有 `implementation_worker` 拥有写入责任，主代理和其他代理不得并行修改共享路径；
- 子代理只返回有界证据和结果，不继续委派下一级代理；
- 主代理重新读取最终差异与验证结果，不把子代理成功返回直接当作完成证据；
- 认证、模型可见性、Plus 限额和实际模型身份均以当前运行时证据为准；配置中的模型名只表示请求目标；
- 没有可观察的令牌或限额数据时标记为不可观察，不推导精确节省比例。

## 运行前检查

从仓库根目录执行：

```bash
python3 .codex/scripts/validate_multi_model_config.py
codex doctor --summary --no-color
```

Codex 只会为已信任项目加载项目级 `.codex/` 配置；命令行参数和 `-c` 配置覆盖又高于项目配置。运行者必须先确认当前项目处于可信状态，并记录所有命令行覆盖。任一配置模型不可见、推理强度不受支持或 Codex 未加载项目配置时，先停止实验并更新本分支映射。模型发布、停用、能力趋同、配置结构或限额规则变化后必须重新执行检查，不自动沿用历史结论。

## 对照实验

每个对照使用同一 `master` 提交、同一任务题面、同一验收断言和彼此隔离的干净工作树。运行结果、评分断言和其他实验组输出不得进入被测会话上下文。

单一模型基线：

```bash
codex exec --ephemeral --json --strict-config -C <基线工作树> -m gpt-5.6-sol -c agents.enabled=false '<同一任务题面>'
```

多模型实验组：

```bash
codex exec --ephemeral --json --strict-config -C <实验工作树> -m gpt-5.6-sol '<同一任务题面和实验启动指令>'
```

实验组使用如下启动指令，并根据实际任务删除不适用角色：

```text
使用当前项目的 Codex 多模型实验配置处理这个任务。
主代理保留目标、权威、决策与最终验证责任。
先把相互独立的只读探索交给 fast_explorer；信息充分后，只让一个 implementation_worker 承担有界写入；完成后由 quality_reviewer 独立复核最终差异。
只有任务涉及方法、重大架构、安全、不可逆决策或关键评估时，才说明触发原因并调用 critical_reviewer。
等待已启动代理结束，重新读取最终状态，并汇总实际模型证据、验证结果、未解决风险和可观察用量。
```

## 评分与结论

盲评者不知道结果来自哪个实验组，并按同一组隐藏断言检查：

1. 需求与仓库权威符合度；
2. 正确性、回归、安全和范围控制；
3. 已执行验证对验收义务的覆盖；
4. 独立复核发现的有效问题和最终残留问题；
5. 总耗时、代理数量、返工轮次、上下文噪声和可观察令牌用量；
6. requested model 与 actual runtime model 的证据是否一致或明确标记为不可观察。

只有多模型组的质量不低于单一模型基线，并且至少在返工、耗时、主线程上下文或可观察用量中的一项取得稳定改善，才形成继续采用的候选结论。一次运行只能作为样本，不能证明长期收益。

## 当前烟雾测试证据

2026-09-08 在本分支执行了配置静态校验和一次最小只读委派烟雾测试：

- `.codex/config.toml` 与 4 个自定义代理 TOML 均可解析；校验脚本确认当前模型目录包含所请求的模型和推理强度；
- `codex --strict-config doctor` 未报告配置解析错误，但发现用户级状态数据库完整性和供应商端点可达性问题；
- 烟雾测试由请求的 `gpt-5.6-sol` 主代理尝试调用 `fast_explorer`，运行轨迹出现 `collab spawn failed: no thread with id`；
- 后续 `wait` 事件的接收代理列表为空，最终回答却声称委派成功，因此退出码 `0` 和最终自述都不能证明子代理实际运行；
- 本次主线程报告 `61,890` 个输入令牌、其中 `37,376` 个缓存输入令牌，以及 `424` 个输出令牌；轨迹没有提供可验证的 Luna 子线程或实际子代理模型身份。

当前结论是：配置结构校验通过，真实多代理链路烟雾测试失败。正式对照实验保持阻塞，直到新的隔离运行能够观察到非空子代理线程、子代理终态和足以区分 requested model / actual runtime model 的证据。不得用本次主代理最终回答补记为成功。

关闭本实验时可以在命令行设置 `-c agents.enabled=false`，或切回不包含本目录配置的 `master`。本分支配置不会自动改变其他分支或使用方项目。
