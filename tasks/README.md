# 任务与临时计划

任务记录只承担工作协调职责，不构成方法、架构或 Skill 契约权威。

## 项目状态入口

项目演进路线、当前阶段、已完成里程碑、当前核心目标和下一步工作统一维护在：

`docs/project/project-roadmap.md`

任务记录不重复维护这些易变化的项目状态；这里只定义工作协调规则。

## 临时计划使用规则

复杂、多步骤、跨新上下文、需要恢复现场或需要显式阶段协调的工作，可以创建临时计划：

```text
tasks/plans/YYYYMMDD/NN-name.md
```

其中：

- `YYYYMMDD` 使用创建日期；
- `NN` 是当日目录内的两位顺序号；
- 文件名使用简短、稳定的英文 kebab-case 描述工作目标，以保持路径和工具兼容性。

简单、单上下文、可以直接安全完成的工作不创建计划。不得为了形式完整性把每次聊天、每个文件修改或每一步操作都转换成任务记录。

临时计划只保存完成当前工作的必要协调信息，例如：

- 目标；
- 权威 / 输入；
- 范围 / 非目标；
- 工作项 / 顺序；
- 阻塞项；
- 完成条件；
- 必要的证据引用。

不要在临时计划中复制已有方法、架构、契约或长期项目知识，也不要保存完整会话推理。

## 知识边界与生命周期

- 会话历史、其他会话和其他项目的工作习惯不能直接成为当前任务的项目事实；
- 任务中产生新的长期结论时，必须回写到对应权威产物；
- 任务与临时计划可以记录临时协调状态，但不能通过任务文本修改方法或 Skill 契约；
- 已存在权威文档时，只保留引用，不在任务中复制一份长期规则；
- 临时运行输出、评估结果和工作区按仓库现有忽略规则处理，不因为出现过就自动升级为长期产物。

## 与执行单元的关系

执行单元是方法中的逻辑执行单位，任务 / 临时计划只是可能的承载或协调方式之一。

一个临时计划可以协调一个或多个工作项，也可以引用执行单元，但不得改变执行单元的方法契约。是否需要持久化任务记录，取决于协调价值，而不是方法阶段是否存在。

## 阶段回写

如果任务产生新的方法决策，应先更新对应方法 / 决策文档；如果实现暴露 Skill 契约问题，应先修改并提交契约，再继续 Skill 实现。

当前项目的详细权威与知识边界以根目录 `AGENTS.md` 为准。
