# 工程术语语义安全与现行文档全量收敛计划

**状态：** 阶段 A — 正式概念语义安全

## 目标

按 Issue #64 推进“工程术语语义安全与现行文档全量收敛 v1”。先建立正式工程概念的稳定中文名称、正式英文身份与定义权威映射，消除中文化可能造成的概念别名、层级漂移和契约语义混淆；完成该前置门禁后，再对当前仓库人类可读文档执行全量扫描与分类收敛。

## 范围

### 阶段 A — 正式概念语义安全

1. 从定义权威恢复正式概念身份；
2. 建立首选中文名称、正式英文身份、定义权威的稳定映射；
3. 消除同一正式概念的冲突中文别名；
4. 区分方法阶段、方法门禁、产物、能力层、技能调用名等不同对象；
5. 在中文表达规则中加入正式概念身份保护门禁；
6. 在 AI 复核中加入翻译语义回归检查；
7. 增加专项项目治理评估，验证 AI 不会因中文表达混淆正式能力层。

### 阶段 B — 现行文档全量扫描

1. 枚举当前提交中的全部人类可读文档；
2. 分类为当前权威 / 当前能力实现与指南 / 当前治理入口 / 历史研究与证据；
3. 对前三类逐文件扫描并修复无必要英文混写、冲突中文别名和正式概念身份漂移；
4. 历史材料纳入扫描清单，但默认不为表面一致性批量重写；
5. 对全量修改执行语义等价复核、专项运行时评估和最终 AI 复核。

## 非目标

- 不改变核心开发方法生命周期；
- 不新增工程能力层；
- 不因中文化重新定义既有能力职责、技能契约或机器标识；
- 不批量重写 Git 历史；
- 不自动合并 PR。

## 当前已确认风险

- `Technology Profile` 在当前高优先级文档中同时出现“技术画像”和“技术配置档”；
- `Verification Profile` 同时出现“验证画像”和“验证配置档”；
- `Runtime Adapter` 出现“运行时适配器”和“运行时适配层”；
- 方法阶段、方法产物与技能调用名仍大量使用同一组英文术语，后续中文化如果不先建立类型化映射，可能把不同对象合并；
- `docs/guides/terminology-guidelines.md` 优先级低于方法、架构与契约，不能仅依赖指南自行覆盖高优先级定义中的冲突译名。

## 完成条件

### 阶段 A

- 正式概念身份在定义权威中可发现；
- 核心能力层没有冲突中文别名；
- 中文表达规则明确“中文化表达不得改变正式概念身份、类型、层级或契约”；
- AI 复核明确检查语言修改造成的语义回归；
- 专项治理评估覆盖技术画像、验证画像、任务型技能、运行时适配器等概念区分；
- 阶段 A 通过 AI 复核后，才进入全量扫描。

### 阶段 B

- 当前仓库全部人类可读文档完成枚举与分类；
- 当前有效文档逐文件完成检查；
- 必要修订通过语义等价复核与运行时评估；
- 最终未解决阻塞 / 中等级问题为 `0 / 0`；
- PR 进入人工集成决策但不自动合并。
