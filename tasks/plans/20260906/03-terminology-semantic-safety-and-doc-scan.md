**状态：** 阶段 A — 等待正式概念语义安全运行时验证

按 Issue #64 推进“工程术语语义安全与现行文档全量收敛 v1”。先建立正式工程概念的稳定中文名称、正式英文身份与定义权威映射，消除中文化可能造成的概念别名、层级漂移和契约语义混淆；完成该前置门禁后，再对当前仓库人类可读文档执行全量扫描与分类收敛。

## 范围

### 阶段 A — 正式概念语义安全

1. 从定义权威恢复正式概念身份；
2. 建立首选中文名称、正式英文身份、定义权威的稳定映射；
3. 识别同一正式概念的冲突中文别名并登记为迁移别名，不在运行时验证前先删除这些真实冲突输入；
4. 区分方法阶段、方法门禁、产物、能力层、Skill 调用名等不同对象；
5. 在中文表达规则中加入正式概念身份保护门禁；
6. 在 AI 复核中加入翻译语义回归检查；
7. 建立两类专项项目治理评估：工程能力层身份，以及方法阶段 / 产物 / 门禁 / Skill 调用名身份；
8. 通过当前项目状态恢复与正式概念语义安全运行时验证后，才进入阶段 B。

### 阶段 B — 现行文档全量扫描

1. 枚举当前提交中的全部人类可读文档；
2. 分类为当前权威 / 当前能力实现与指南 / 当前治理入口 / 历史研究与证据；
3. 对前三类逐文件扫描并修复无必要英文混写、冲突中文别名和正式概念身份漂移；
4. 历史材料纳入扫描清单，但默认不为表面一致性批量重写；
5. 对全量修改执行语义等价复核、专项运行时评估和最终 AI 复核。

## 非目标

- 不改变核心开发方法生命周期；
- 不新增工程能力层；
- 不因中文化重新定义既有能力职责、技能契约或机器标识；
- 不批量重写 Git 历史；
- 不自动合并 PR。

## 当前已确认风险

- `Technology Profile` 在当前高优先级文档中同时出现“技术画像”和“技术配置档”；
- `Verification Profile` 同时出现“验证画像”和“验证配置档”；
- `Runtime Adapter` 出现“运行时适配器”和“运行时适配层”；
- 方法阶段、方法产物与 Skill 调用名仍大量使用同一组英文术语，后续中文化如果不先建立类型化映射，可能把不同对象合并；
- `docs/guides/terminology-guidelines.md` 优先级低于方法、架构与契约，因此最高权威 `AGENTS.md` 已明确：术语映射只解析名称身份，正式职责仍以定义权威为准；不能依赖翻译覆盖上游语义。
