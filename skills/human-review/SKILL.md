# 人工评审

## 目的

把当前需求、功能规格、架构或技术方案整理成便于人工理解和判断的结构化评审材料，并把人工确认产生的语义变化准确返回真实语义所有者。

本 Skill 只面向 Consumer 软件项目，不用于 `agentic-dev` 自身的方法论演进、Issue / PR 决策或能力设计过程。

人工评审的长期边界、派生视图生命周期、反馈分类和交付投影契约由 `architecture:human-review` 持有；本 Skill 只负责稳定执行该契约，不复制第二套规范语义。

## 触发条件

满足以下任一情况时可以调用：

- 当前 Method / Skill 将事项判断为必须人工评审；
- 当前 Method / Skill 将事项判断为建议人工评审；
- 用户、客户、产品、架构或工程责任人明确要求人工评审材料；
- 需要通过跨模块流程、生命周期、角色关系等综合视角发现当前权威内容是否存在缺口。

普通局部、低风险、可逆且现有权威内容已能唯一决定结果的工作，不因为本 Skill 存在而自动进入人工评审。

## 输入

- 当前评审目标与范围；
- 直接相关的需求、功能规格、架构或技术方案语义所有者；
- 必要的上下游关系；
- 当前未决歧义、冲突、临时默认或待决事项；
- Consumer 的语言与术语规范；
- 当前写入授权；
- 可选的交付目标，默认 `delivery_target = none`；
- 如果显式要求最终交付，可选的客户模板、Consumer 本地文档规范和目标办公环境。

不得为了生成“完整评审材料”默认读取全量项目文档、archive 或无关实现。

## 流程

1. **确认评审责任**
   - 确认当前对象属于 Consumer 软件项目；
   - 明确评审目标、范围和受众；
   - 判断当前状态是必须评审、建议评审还是仅因人工明确请求而评审；
   - 不自行扩大产品、架构或技术责任。

2. **读取最小权威上下文**
   - 读取当前评审目标直接需要的真实语义所有者；
   - 只补充能够改变当前判断的上游 / 下游权威内容；
   - 区分当前权威内容、历史证据、临时分析和未决材料。

3. **生成结构化 Markdown 评审草稿**
   - 默认只输出结构化 Markdown；
   - 按当前内容选择必要部分，不强制固定模板；
   - 优先表达评审目标、已确认事实、当前方案、角色责任、主要流程 / 生命周期、规则与状态、边界 / 失败行为、验收、差异、待确认项和已发现缺口；
   - 不为了形式完整制造不存在的章节或额外业务机制。

4. **按需形成临时辅助视图**
   - 只有明显提升理解或判断效率时，才建议或生成流程图、泳道图、状态图、思维导图、关系图、矩阵、架构图或时序图等临时视图；
   - 视图必须能够从当前 Markdown / 权威内容重新生成；
   - 不建立持久 BPMN、UML 或业务模型中间层；
   - 图形中发现的新语义问题返回真实语义所有者。

5. **执行人工评审并分类反馈**
   - 展示反馈：只修改评审投影；
   - 语义修正：回写原真实语义所有者；
   - 新增长期决定：提升到适当的需求、功能规格、架构或技术方案语义所有者；
   - 未决问题：保持未决，不伪装成已确认事实；
   - 一条反馈同时包含展示和语义变化时拆分处理。

6. **回写长期语义**
   - 有写入授权时，更新真实语义所有者；
   - 完成写入后必须重新读取真实语义所有者，确认人工决定已经实际进入当前权威内容；
   - 没有写入授权时，输出明确的待执行权威回写动作，并把当前状态标记为 **待权威回写 / 评审未完成**；
   - 缺少写权限时允许当前执行返回，但不得声称人工评审已经完成、语义已经收敛或权威内容已经更新；
   - 不在下游文件中静默覆盖上游需求或架构事实；
   - 不让人工决定长期停留在聊天、评审草稿或图形中。

7. **重新生成并核对评审草稿**
   - 只有在长期语义已实际回写并重新读取确认后，才以更新后的当前权威内容重新生成或校准最终评审草稿；
   - 确认没有长期事实只存在于草稿、图形、会话或待执行回写动作中；
   - 确认临时投影没有成为第二套当前权威内容；
   - 如果仍处于待权威回写状态，本步骤只能保留工作草稿用于后续恢复，不能把它标为最终收敛结果。

8. **处理交付目标**
   - `delivery_target = none` 时，只有满足人工评审完成条件才以“评审完成”退出；
   - 调用方明确要求最终格式时，先确认内容状态和目标格式，再按 `architecture:human-review` 的交付投影契约执行；
   - 处于待权威回写状态时，不得生成正式已确认交付物；如人工明确要求输出中间版本，只能作为“草案 / 待确认”交付；
   - 交付投影只能使用当前确认的 Markdown / 权威内容，不通过渲染重新解释业务、架构或技术语义；
   - 如果运行环境缺少真实文件生成或目标格式验证能力，明确报告能力缺口并保留已确认 Markdown 输入，不得声称已经生成或验证文件。

9. **生成 HTML 交互评审视图（仅在显式要求时）**
   - `delivery_target = html` 时，按 `architecture:human-review` 的 HTML 契约生成静态、轻量评审视图；
   - 只实现当前评审真正需要的导航、展开 / 收起、有限筛选、待确认项突出和临时图形等交互；
   - 不为交互效果引入新的业务系统、后台服务或持久事实源；
   - 评审尚未收敛或仍待权威回写时，清楚标识草稿和待确认状态。

10. **生成 DOCX 正式文档（仅在显式要求时）**
    - `delivery_target = docx` 时，先按 `architecture:human-review` 确定模板优先级、内容状态和正式文档要求；
    - 正式 DOCX 只能使用已经实际回写并重新读取确认的收敛内容；
    - 评审未收敛或仍待权威回写时，只有人工明确要求才能输出 DOCX，并且必须标识“草案 / 待确认”；
    - 按客户模板、Consumer 本地规范或通用中文正式办公文档默认配置生成，不在本 Skill 复制另一套格式规范。

11. **验证最终交付物**
    - 核对交付物与已确认 Markdown / 当前权威内容的语义一致性；
    - 按 `architecture:human-review` 对目标格式执行相应的结构、字体、分页、交互或兼容性验证；
    - 只有真实生成并实际完成相应验证后，才声明目标交付物完成。

## 输出

默认输出：

- 结构化 Markdown 评审草稿；
- 已发现的缺口、冲突、待确认事项；
- 人工反馈分类结果；
- 已完成并重新读取验证的权威回写；或缺少授权时的待执行权威回写动作与 **待权威回写 / 评审未完成** 状态；
- 必要的临时辅助视图或视图建议。

只有显式要求最终格式时，才额外输出对应交付物及其验证结果。v1 的直接交付重点为：

- `html`：交互式人工审核视图；
- `docx`：正式需求分析或设计确认文档。

`pdf`、`xlsx`、`pptx` 等可以按 Consumer 实际能力扩展，但本 Skill 不要求一次性支持全部格式，也不为每种格式建立独立 Skill。

## 退出条件

### 完成退出

只有同时满足以下条件时，才能把本次人工评审标记为完成：

- 评审范围明确；
- 需要人工判断的高价值问题已处理或明确保持未决；
- 所有已经确认的长期语义变化都已实际回写真正语义所有者；
- 已重新读取对应当前权威内容，并确认回写真实存在且没有冲突；
- 评审草稿已基于重新读取后的当前权威内容重新生成或校准；
- 不存在只保存在草稿、图形、会话或待执行回写动作中的长期事实；
- 没有显式交付要求时已经停止在结构化 Markdown 评审草稿；
- 有显式交付要求时，只有真实目标文件和相应验证已经完成，或已明确报告无法完成的文件能力缺口；
- 本次评审没有被错误解释为合并、发布、部署或独立变更复核授权。

### 阻塞 / 待回写返回

如果人工已经作出长期语义决定，但因为缺少写入授权或其他外部权限尚未完成权威回写：

- 当前执行可以返回；
- 必须输出待执行权威回写动作；
- 必须明确状态为 **待权威回写 / 评审未完成**；
- 不得声称语义已收敛、评审已完成或正式交付已就绪；
- 后续执行必须先完成并重新读取验证权威回写，再重新判断完成条件。

## 升级

以下情况返回真实责任层或人工权威，不由本 Skill 自行决定：

- 需求 / 产品歧义或权威冲突；
- 高影响、高成本难逆架构决定超出当前授权；
- 安全、隐私、生产或不可逆数据风险；
- 语义所有者无法唯一确定；
- 外部合同、法规或组织流程要求特殊正式交付物成为权威依据；
- 当前请求实际是独立仓库变更复核，应使用 `review-change` 而不是本 Skill；
- 当前运行环境无法真实生成或验证所要求的最终文件格式。

人工评审通过不等于仓库变更复核通过，也不授予集成或外部操作权限。
